# ADRemote · 安卓被控端 + 网页控制台

## 简介

自用的安卓远程协助方案：**手机当被控端共享屏幕，浏览器当控制端**。
手机不开放任何入站端口，主动出站连到你自己的一台中继，浏览器打开同一个地址就能看到画面并操作。

- 被控端：Android 10 及以上，屏幕采集走 `MediaProjection`，操作注入走无障碍 `dispatchGesture`
- 控制端：Chrome / Edge，`WebCodecs` 硬解 H.264，局域网延迟通常 80–200 ms
- 中继：Node.js 单进程，一个端口（默认 3389）同时提供 HTTPS 页面、REST API 和 WSS
- 每次控制都必须由手机端本人确认，15 秒不操作自动拒绝；任一侧都能随时断开

和常见的"远控软件"最大的区别是：**没有任何隐藏、常驻后台偷跑、绕过授权的行为**。
会话期间手机前台服务常驻通知，通知栏有一键断开，服务端还留审计日志。

---

## 功能

- **实时画面**：H.264 硬编硬解，四档画质（流畅 / 均衡 / 高清 / 原画），切换时重建编码器
- **实时操作**：单击、滑动、拖拽、长按拖动（拖图标、拖小组件）、键盘返回
- **多指触控**：双指缩放、三指手势
- **声音同步**：手机音频走同一条 WebSocket，网页端直接播放，可随时静音
- **音量控制**：网页端滑块直接调手机媒体音量
- **文字输入**：优先写入当前聚焦输入框，找不到就退回剪贴板
- **状态浮层**：码率、帧率、延迟、上下行速率、流量，可逐项开关
- **两种部署模式**：中继模式（推荐）和直连模式（手机自己当服务器，仅适合同一 WiFi）

## 它是怎么连的

    浏览器 ──HTTPS/WSS(3389)──▶ 中继服务器 ◀──WSS 出站── 安卓被控端
       │ 登录 / 请求控制            │ 鉴权 + 会话撮合            │ 采集 + 编码
       └────── 画面 H.264 ◀─────────┴──────── 视频 / 音频帧 ◀─────┘
       控制指令 ──▶ 无障碍 dispatchGesture

三个角色先分清，这里最容易填错：

| 角色 | 是什么 | 要填什么 |
|---|---|---|
| 被控端 | 你的手机，主动出站连中继 | App 里的「中继服务器地址」填中继那台机器的 IP |
| 中继 | 跑 `node server.js` 的电脑或 VPS | 不需要填任何地址 |
| 控制端 | 浏览器 | 打开 `https://<中继地址>:3389` |

**不要**在手机里填手机自己的 IP —— 手机在 NAT 后面、不监听端口，浏览器根本连不进来，
填自己的地址等于让 App 连自己，必然报 `Failed to connect`。

## 使用说明

### 一、部署中继（需要 Node.js 18+）

    cd server
    npm install

    # 生成自签证书（换成你实际访问用的 IP / 域名）
    bash scripts/gen-cert.sh 192.168.1.10 remote.example.com

    # 启动，默认监听 0.0.0.0:3389
    node server.js

Windows 上不需要 WSL：

    cd server
    npm install
    node scripts/gen-cert.js
    $env:PORT=3389; node server.js

> 必须用 HTTPS。浏览器只在安全上下文下提供 `VideoDecoder`，用 `http://` 打开页面能进，但画面解不出来。
> 自签证书在浏览器里点「高级 → 继续前往」即可。
>
> Windows 注意：3389 默认被「远程桌面(RDP)」占用，冲突会直接报 `EADDRINUSE`。
> 关掉远程桌面，或换端口：`$env:PORT=8443; node server.js`，手机 App 和路由器映射同步改。

### 二、安装 App

下载本页 Release 附件里的 `ADRemote-1.21-debug.apk`，允许「安装未知来源应用」后安装。

首次打开按顺序做四件事：

1. 填「中继服务器地址」，例如 `https://192.168.1.10:3389`
2. 打开「允许自签证书」（用自签证书时必须开）
3. 填账号密码登录（首次可在网页端注册，或点 App 里的「注册」）
4. 点「开启无障碍」→ 在系统列表里打开 **ADRemote 远程操作**
   （没有它只能看屏幕、不能操作；可选再给悬浮窗权限，后台收到请求能直接弹确认框）

然后点「上线待命」→ 系统弹出录屏授权 → 允许。通知栏出现「在线待命」就绪。

### 三、开始控制

1. 浏览器打开 `https://<服务器>:3389`，登录同一账号
2. 设备列表里点「请求控制」
3. 手机弹出确认框（或通知栏「允许控制 / 拒绝」），**15 秒不操作自动拒绝**
4. 允许后画面出现。工具栏：返回 / 主屏 / 最近任务 / 输入文字 / 画质 / 音量 / 全屏 / 断开

操作方式：

- 单击 = 点按，滚轮 = 上下滑动，按住拖动 = 拖拽
- **长按拖动**：按住不动约 0.3 秒再拖，才能拖桌面图标和小组件
- 双指 / 多指：手机上正常的缩放手势，网页端用触屏或触控板直接做
- `Esc` / `Backspace` = 返回键
- 断开：网页点断开，或手机通知栏「立即断开」

### 四、要在外网使用？

**不要把 3389 直接暴露到公网。** 请配合内网穿透项目使用：

    https://github.com/Air-Air3s/AndroidFrp

用它把中继的 3389 映射出去，手机和浏览器都连穿透后的地址，公网只暴露 FRP 服务端的入站端口。
这样中继本身仍然待在防火墙后面，比直接开端口安全得多。

如果一定要公网直连中继，至少加一层 Nginx / Caddy 反代 + IP 白名单，
或者只放行固定 IP 访问 3389。

## v1.21 更新内容

这一版解决的是「顶栏显示已连接，但画面一帧都没有」的假死。根因在发送端把采集线程卡死了：
编码线程直接同步写 socket，上行一旦扛不住当前码率，`write` 就阻塞在发送缓冲区，
整条采集管线跟着停住。

- **发送队列化**：编码线程只把帧塞进 64 帧队列，真正写 socket 在独立线程，队列满了直接丢非关键帧。
  采集再也不会被网络拖住
- **码率下调**：流畅 0.7 Mbps / 均衡 1.6 Mbps / 高清 3 Mbps / 原画上限 8 Mbps
  （像素系数 0.12 → 0.06，之前的原画档在 1080×2400 上要 10 Mbps，公网必卡）
- **写失败即断连**：以前写异常只置标志位不关 socket，网页端会一直保持"已连接"的假象
- **网页首帧看门狗**：6 秒没画面自动要关键帧并降到「流畅」重试，再等 7 秒仍无画面就明确提示
  （上行带宽不足 / 共享被系统收回），不再只给黑屏
- **中继重连修复**：App 断线重连后把未结束的会话重新绑到新连接
  （以前 `sessionId` 一律置空，重连后所有帧都因找不到会话被丢掉）
- **心跳放宽**：连续 3 次无响应才判定掉线，断开后给 20 秒重连宽限

## 安全设计

| 项 | 做法 |
|---|---|
| 口令 | scrypt 加盐散列，不存明文 |
| 令牌 | HMAC-SHA256 签名，12 小时过期，登录失败按 IP 限速 |
| 授权 | 每次会话手机端显式确认，15 秒超时自动拒绝 |
| 最小可见 | 会话期间前台服务常驻通知 + 一键断开 |
| 传输 | TLS 1.2+，自签证书需在 App 内显式开启才放宽校验 |
| 审计 | `data/audit.log` 记录登录、请求、开始、结束、时长、帧数、字节数 |
| 数据面 | 服务端只转发字节，不落盘、不解析视频内容 |

## 已知限制

1. 锁屏、支付密码框、部分银行 App 的安全键盘会屏蔽无障碍手势，点不进去（系统防护，无解）
2. 拖拽是「抬手回放」：`dispatchGesture` 下发后无法中途追加轨迹，所以拖拽在抬手时一次发出；单击和滑动是实时的
3. 文字输入找不到输入框时退回剪贴板，需要在手机上长按粘贴
4. 息屏时画面是黑的，亮屏后等一个关键帧自动恢复
5. 旋转屏幕会重建采集管线，约 0.3–0.8 秒黑屏
6. 个别机型硬编码器只支持特定 profile，代码里已做回退，极少数老机型原画档会自动退回高清

## 合规提醒

这套东西只适合**你自己拥有的设备**，或**明确知情并同意**的人的设备。

不要用它去控制任何未明确同意的人的手机；不要加隐藏图标、静默自启、绕过授权弹窗之类的功能。
国内对远控类工具的法律边界很清楚：被控端必须知情、必须可随时中止、必须有可见提示与操作日志 —— 这三点本项目都做了。
