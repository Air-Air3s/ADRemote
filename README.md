# ADRemote · 安卓被控端 + 网页控制台

## 简介

自用的安卓远程协助方案：**手机当被控端共享屏幕，浏览器当控制端**。

默认走**直连模式**：手机自己开一个 HTTPS + WSS 服务（3389），浏览器直接连手机，
不需要服务器、不需要中转、不需要注册，同一 WiFi 下装完就能用。

要出门在外也能连？**不用买 VPS** —— 配合我的另一个项目
[AndroidFrp](https://github.com/Air-Air3s/AndroidFrp)（跑在同一台手机上），
把手机的 3389 映射到 frp 平台的公网地址，浏览器打开公网地址即可。

- 被控端：Android 10 及以上，屏幕采集走 `MediaProjection`，操作注入走无障碍 `dispatchGesture`
- 控制端：Chrome / Edge，`WebCodecs` 硬解 H.264，局域网延迟通常 80–200 ms
- 每次控制都必须由手机端本人确认，15 秒不操作自动拒绝；任一侧都能随时断开
- 全程没有任何隐藏、常驻偷跑、绕过授权的行为：会话期间前台服务常驻通知，通知栏一键断开

---

## 三种用法

| 形态 | 适合场景 | 需要服务器 | 浏览器打开 |
|---|---|---|---|
| **直连** | 手机和电脑在同一个 WiFi | 不需要 | `https://<手机IP>:3389` |
| **直连 + 内网穿透** | 人在外面，要连回家里的手机 | 不需要 | `https://<平台公网地址>` |
| 中继 | 多台手机、想隐藏手机 IP | 需要一台 VPS | `https://<中继IP>:3389` |

先用直连跑通，再叠加穿透出外网。中继只在特殊需求下才用。

---

## 功能

- **实时画面**：H.264 硬编硬解，四档画质（流畅 / 均衡 / 高清 / 原画），切换时重建编码器
- **实时操作**：单击、滑动、拖拽、长按拖动（拖图标、拖小组件）、键盘返回
- **多指触控**：双指缩放、三指手势
- **声音同步**：手机音频走同一条连接传到网页端，可随时静音
- **音量控制**：网页端滑块直接调手机媒体音量
- **文字输入**：优先写进当前聚焦输入框，找不到就退回剪贴板
- **状态浮层**：码率、帧率、延迟、上下行速率、流量，可逐项开关
- **零依赖网页端**：原生 JS，无框架、无构建步骤

## 它是怎么连的

直连模式（默认）：

    浏览器 ──HTTPS/WSS──▶ 手机 3389（ADRemote 直连服务）
       │ 登录 / 请求控制            │ 采集 + 编码
       └──── 画面 H.264 ◀───────────┘
       控制指令 ──▶ 无障碍 dispatchGesture

出外网时在手机上加一层 frp：

    浏览器 ──HTTPS──▶ frp 平台公网地址 ──▶ frps ◀──frpc── 手机 127.0.0.1:3389

中继模式（可选）：

    浏览器 ──HTTPS/WSS──▶ 中继服务器 ◀──WSS 出站── 手机

**只有一个角色容易填错**：App 里的地址栏填的是「浏览器要连的那台机器」。
直连模式填手机自己的 IP，中继模式填中继的 IP，**永远不要在中继模式里填手机的 IP**
——手机不监听入站端口，那等于让 App 连自己，必报 `Failed to connect`。

## 使用说明

### 一、直连模式（推荐，先跑通这个）

1. 安装 `ADRemote-1.21-debug.apk`（Android 10+）
2. 打开 App，勾选 **「直连模式（手机自己开 3389，浏览器直接连）」**
   —— 勾上后中继地址栏隐藏，按钮变成「保存凭据」
3. 填账号密码（随便设，只在本机生效，**直连不需要注册**）→ 点「保存凭据」
4. 点「开启无障碍」→ 系统列表里打开 **ADRemote 远程操作**
   （没有它只能看屏幕、不能操作；可选再给悬浮窗权限）
5. 点「上线待命」→ 允许录屏 → 状态卡片显示 `直连中 · https://192.168.x.x:3389`
6. 同一 WiFi 的电脑上浏览器打开这个地址 → 证书提示点「高级 → 继续前往」
   → 用刚才的账号密码登录 → 设备列表点「请求控制」→ 手机 15 秒内点「允许」

三个容易踩的点：

- 证书**每次启动现场生成**，所以每次重启 App 浏览器都会再提示一次证书不受信任，正常
- 网页是**打包进 APK** 的，改了网页必须重新编译 APK 才生效
- 手机 IP 变了地址就失效，建议在路由器里给手机做 DHCP 保留

### 二、出外网：直连 + AndroidFrp（不需要服务器）

手机跑 [AndroidFrp](https://github.com/Air-Air3s/AndroidFrp)，它在本机以子进程方式拉起
官方 `frpc` 内核，把手机本地的 3389 映射到 frp 平台的公网地址。平台支持
ChmlFrp / ME Frp / MSLfrp，注册后在 App 里登录、勾选隧道、一键启动即可。

隧道配置只有三个字段要填对：

| 字段 | 填什么 | 为什么 |
|---|---|---|
| 隧道类型 | **TCP** | 选 HTTP 的话平台会终止 TLS，而手机只讲 HTTPS，握手直接失败 |
| 本地地址 | `127.0.0.1` | frpc 和 ADRemote 在同一台手机上 |
| 本地端口 | `3389` | 直连模式的固定端口 |

启动顺序：ADRemote 先「上线待命」（显示 `直连中`）→ AndroidFrp 启动隧道
（日志出现 `start proxy success`）→ 浏览器打开 `https://<平台域名>:<公网端口>`。

保活是这类用法断线的头号原因，两个 App 都要处理：ADRemote 允许自启动 / 后台运行、
电池优化设为「不限制」；AndroidFrp 走「设置 → 保活体检」逐项授权，保活强度选**强力**
（熄屏也要稳就选**极限**，更耗电）。国产 ROM 还要单独开「自启动」「后台运行」「锁定后台」。

⚠️ 这条路把手机的登录页直接摆到了公网上，请务必：用强密码、用平台分配的随机高位端口、
**用完就停隧道**，不要长期挂着。

### 三、中继模式（可选）

需要一台跑 Node.js 18+ 的机器：

    cd server
    npm install
    bash scripts/gen-cert.sh 192.168.1.10 remote.example.com
    node server.js

Windows 上不需要 WSL：

    cd server
    npm install
    node scripts/gen-cert.js
    $env:PORT=3389; node server.js

> Windows 上 3389 默认被「远程桌面(RDP)」占用，会报 `EADDRINUSE`。
> 关掉 RDP，或换端口：`$env:PORT=8443; node server.js`，手机地址同步改。

然后：浏览器打开 `https://<服务器IP>:3389` 注册账号 → App 里取消勾选直连、填中继地址、
打开「允许自签证书」→ 登录 → 开无障碍 → 上线待命 → 网页端请求控制。

环境变量：`PORT`(3389) / `HOST`(0.0.0.0) / `DATA_DIR`(./data) / `CERT_DIR`(./certs) /
`ALLOW_REGISTER`(1) / `ADREMOTE_SECRET`(自动生成)。防火墙只需放行一个 TCP 端口。

### 四、网页端怎么操作

工具栏：**返回 / 主屏 / 最近任务 / 输入文字 / 画质 / 音量 / 全屏 / 断开**

- 单击 = 点按，滚轮 = 上下滑动，按住拖动 = 拖拽
- **长按拖动**：按住不动约 0.3 秒再拖，才能拖桌面图标和小组件
- 双指缩放：触屏 / 触控板双指捏合，或手机上正常的多指手势
- `Esc` / `Backspace` = 返回键
- 画质四档随时切；局域网直接上「高清」/「原画」，走 frp 或 4G 先用「流畅」
- 声音会同步过来，可随时静音；音量滑块直接调手机媒体音量

## v1.21 更新内容

这一版解决的是「顶栏显示已连接，但画面一帧都没有」的假死。根因在发送端把采集线程卡死了：
编码线程直接同步写 socket，上行一旦扛不住当前码率，`write` 就阻塞在发送缓冲区，
整条采集管线跟着停住。

- **发送队列化**：编码线程只把帧塞进 64 帧队列，真正写 socket 在独立线程，队列满了直接丢非关键帧。
  采集再也不会被网络拖住
- **码率下调**：流畅 0.7 Mbps / 均衡 1.6 Mbps / 高清 3 Mbps / 原画上限 8 Mbps
  （像素系数 0.12 → 0.06，之前的原画档在 1080×2400 上要 10 Mbps，公网必卡）
- **写失败即断连**：以前写异常只置标志位不关 socket，网页端会一直保持"已连接"的假象
- **网页首帧看门狗**：6 秒没画面自动要关键帧并降到「流畅」重试，再等 7 秒仍无画面就明确提示
  （上行带宽不足 / 共享被系统收回），不再只给黑屏
- **中继重连修复**：App 断线重连后把未结束的会话重新绑到新连接
  （以前 `sessionId` 一律置空，重连后所有帧都因找不到会话被丢掉）
- **心跳放宽**：连续 3 次无响应才判定掉线，断开后给 20 秒重连宽限

## 安全设计

| 项 | 做法 |
|---|---|
| 口令 | scrypt 加盐散列，不存明文 |
| 令牌 | HMAC-SHA256 签名，12 小时过期，登录失败按 IP 限速 |
| 授权 | 每次会话手机端显式确认，15 秒超时自动拒绝 |
| 最小可见 | 会话期间前台服务常驻通知 + 一键断开 |
| 传输 | TLS 1.2+；自签证书需在 App 内显式开启才放宽校验 |
| 审计 | 中继模式记录登录、请求、开始、结束、时长、帧数、字节数 |
| 数据面 | 只转发字节，不落盘、不解析视频内容 |

## 已知限制

1. 锁屏、支付密码框、部分银行 App 的安全键盘会屏蔽无障碍手势，点不进去（系统防护，无解）
2. 拖拽是「抬手回放」：`dispatchGesture` 下发后无法中途追加轨迹，所以拖拽在抬手时一次发出；单击和滑动是实时的
3. 文字输入找不到输入框时退回剪贴板，需要在手机上长按粘贴
4. 息屏时画面是黑的，亮屏后等一个关键帧自动恢复
5. 旋转屏幕会重建采集管线，约 0.3–0.8 秒黑屏
6. 个别机型的硬编码器只支持特定 profile，代码里已做回退，极少数老机型原画档会自动退回高清

## 合规提醒

这套东西只适合**你自己拥有的设备**，或**明确知情并同意**的人的设备。

被控端必须知情、必须能随时中止、必须有可见提示与操作日志 —— 这三点本项目都做了。
不要用它去控制任何未明确同意的人的手机；不要加隐藏图标、静默自启、绕过授权弹窗之类的改造；
也不要用 frp 平台把未备案的 Web 服务对外提供访问。
